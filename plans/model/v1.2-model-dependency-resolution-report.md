# Model v1.2: Dependency Resolution Report

## Status

`Status: Ready for Traceability`

آزمایش‌ها نشان دادند که importهای Model در `CteInfoUser.kt` علت compile-time edge فعلی هستند، نه مصرف فعال Model در Query Builder execution path. وقتی importها و edge با هم موقتاً حذف شدند، Builder و downstreamهای داخلی خواسته‌شده assemble شدند. تصمیم دائمی دربارهٔ edge به دلیل نبود شواهد مصرف‌کنندگان بیرونی `Unresolved` می‌ماند.

## Objective


هدف تشخیص نیاز compile/runtime/API و سازگاری داخلی است. همهٔ تغییرهای آزمایشی قبل از پایان byte-for-byte بازگردانده شدند. هیچ تغییر دائمی در source یا Gradle انجام نشد.

## Decision

```text
Decision: Unresolved
```

**Evidence:** dependency با importهای فعلی compile-time لازم است؛ حذف edge به‌تنهایی در وضعیت فعلی source شکست می‌خورد. هر دو import در body unused هستند؛ حذف موقتشان build Builder را موفق کرد. در آزمایش ترکیبی، Builder و downstreamهای داخلی خواسته‌شده بدون edge assemble شدند. هیچ Model typeای در public API Builder expose نمی‌شود.

**تفسیر:** edge برای active Query Builder execution path یا public API لازم نیست، ولی source فعلی تا زمانی که دو import باقی‌اند برای compilation به artifact نیاز دارد. با حذف آن source references، شواهد داخلی به نفع حذف Gradle edge هستند.

**چرا unresolved:** external consumer evidence در دسترس نیست؛ امکان اتکای مصرف‌کنندگان بیرونی به artifact/runtime resolution عبوری را نمی‌توان از repository رد کرد. این تنها compatibility evidence لازم برای تبدیل پیشنهاد حذف به تصمیم قطعی است.

## Evidence Summary

- importهای `Users` و `UserPhones` تنها source reference فعال Model در Builder هستند و در بدنه مصرف نمی‌شوند.
- هر دو import حذف‌شده با edge حاضر: `:data_base:query:builder:build` موفق.
- edge حذف‌شده با importهای اولیه: build در `compileKotlin` با دو `Unresolved reference 'models'` شکست خورد.
- حذف ترکیبی importها و edge: Builder assemble موفق.
- در همان وضعیت ترکیبی، dialect، renderer، executor، example و migration executor همگی assemble شدند.
- Model type در public API Builder وجود ندارد.
- history تنها commit اولیه دارد و intent را مشخص نمی‌کند.
- فایل‌های موقت دقیقاً به بایت‌های اولیه بازگردانده شدند؛ هیچ تغییر دائمی source یا Gradle اعمال نشد.

## Final Recommendation

`query:builder → models:eloquent`: dependency در active execution/API لازم نیست و آزمایش‌ها نشان دادند پس از حذف importهای بلااستفاده، Builder و downstreamهای داخلی بدون آن build می‌شوند. با این حال، تصمیم حذف دائمی `Unresolved` است تا سازگاری consumerهای بیرونی بررسی شود. این گزارش dependency یا importها را حذف نمی‌کند.
