# v1.3 Implementation Verification

## Scope

این مرحله فقط verification بود. فایل‌های source، test، Gradle، documentation و plan در این مرحله ویرایش نشدند؛ تست جدیدی هم ساخته نشد. گزارش بر اساس source فعلی، تست موجود، خروجی Gradle و dependency graph تهیه شده است.

## Contract Verification

| Contract | نتیجه |
|---|---|
| `table(KClass<T>, alias: String? = null)` | در `IQueryTableApi` وجود دارد؛ با contract منطبق است. |
| `column(KClass<T>, KProperty1<T, R>)` | در `IQueryColumnsApi` وجود دارد؛ با contract منطبق است. |
| نام واقعی جدول/ستون | از `QBTable.name` و `QBColumn.name` resolve می‌شود؛ fallback به نام property مشاهده نشد. |
| aliasهای پیش‌فرض و صریح | رفتار پیش‌فرض و override/clear در Builder و تست‌های موجود مشاهده و تأیید شد. |
| AST و Renderer | Builder مقادیر resolve‌شده را در AST موجود قرار می‌دهد؛ Renderer هیچ reference مستقیمی به Model یا annotation ندارد. |

## Existing Test Results

تست موجود `data_base/query/builder/src/test/kotlin/ast/select_builder/TypedModelReferenceTest.kt` بدون تغییر اجرا شد. خروجی XML: **۹ تست، ۰ failure، ۰ error، ۰ skipped**؛ Gradle نیز `BUILD SUCCESSFUL` گزارش کرد. Gradle همه taskهای این اجرا را `UP-TO-DATE` اعلام کرد، بنابراین نتیجه مبتنی بر خروجی معتبر قبلی همان تست‌ها در این workspace است.

تست‌ها رفتارهای metadata، ترتیب ثبت select/table، aliasها، validation، String API، Renderer و نگاشت `Users.userAge` به نام DB برابر `age` را پوشش می‌دهند. تست validation مربوط به metadata ناقص در یک تست واحد چهار حالت را assert می‌کند.

## Builder Verification

`QueryTableBuilder` و `QueryColumnsBuilder` annotationها را با Kotlin reflection در مرحله ساخت query می‌خوانند، مقدارهای خالی/مفقود را با `IllegalArgumentException` رد می‌کنند و رشته‌های resolve‌شده را در ASTهای معمولی می‌نویسند. `ModelTableAliasContext` یک state داخلی query است و ستون‌های typed ثبت‌شده را با alias مؤثر همان Model همگام می‌کند؛ `QueryRenderSelectBuilder` همین context را به Builderهای select و table می‌دهد.

AST جدید مختص Model مشاهده نشد. APIهای String موجود نیز باقی هستند. اعتبارسنجی صرفاً بر اساس metadata خواسته‌شده انجام می‌شود؛ نوع Kotlin property برای inference نوع SQL یا سازگاری operator استفاده نمی‌شود.

## API Verification

امضای table typed در `IQueryTableApi` generic bound را روی `IModelBase` اعمال می‌کند. امضای column typed در `IQueryColumnsApi` نیز `<T : IModelBase, R>` է. `R` فقط generic տիպ property-reference است؛ source مسیر موردبررسی از آن نوع DB یا SQL نتیجه‌گیری نمی‌کند. هر دو interface، APIهای قبلی String/block را نیز نگه می‌دارند.

## Metadata Resolution

Table resolution از `QBTable.name` و `QBTable.alias` استفاده می‌کند. Column resolution از `QBColumn.name` و `QBColumn.alias` استفاده می‌کند. نبودن annotation جدول/ستون و خالی بودن نام جدول/ستون با `IllegalArgumentException` رد می‌شود. تست repository model تأیید می‌کند `Users::userAge` به `age` تبدیل می‌شود و SQL شامل `userAge` نیست.

## Alias Context Verification

alias صریح و غیرخالی جدول جایگزین default می‌شود؛ `null` default مدل را نگه می‌دارد. تست‌های موجود هر دو ترتیب اجرای `select` و `table` را پوشش می‌دهند و qualifier ستون typed را با alias مؤثر هماهنگ می‌کنند.

نکتهٔ قرارداد: در `QueryTableBuilder`، alias صریح `""` به همان مقدار خالی در AST نوشته می‌شود، نه `null`. Renderer فعلی رشتهٔ خالی را sentinel بی‌alias می‌داند و تست تأیید می‌کند SQL بی‌alias تولید می‌شود. بنابراین رفتار SQL مورد انتظار تأیید است، اما AST مقدار را به‌صورت `""` نگه می‌دارد.

## Renderer Verification

Rendererهای موجود فقط AST و رشته‌های resolve‌شده را مصرف می‌کنند. جست‌وجوی source renderer و AST برای `QBTable`، `QBColumn`، `IModelBase`، `KClass` و `KProperty` referenceی نیافت. تست‌های renderer خروجی qualifier مؤثر، default/explicit SELECT alias و حذف aliasهای پاک‌شده را تأیید می‌کنند.

## String API Regression

تست موجود مسیر `table("users", "u")` و `tableColumn("u", "id")` را اجرا کرده و مقدارهای AST را بررسی می‌کند. APIهای String در interface و Builder همچنان موجودند. نتیجه: PASS برای سازگاری رفتار بررسی‌شده.

## Dependency Verification

فایل Gradle ماژول `query:builder`، `core`، `query:ast` و `query:api` را در production dependencies دارد؛ `models:eloquent` در `testImplementation` است. خروجی واقعی `:data_base:query:builder:dependencies --configuration runtimeClasspath` نیز فقط core، query AST، query API و Kotlin dependencies را نشان داد و `models:eloquent` را در runtime graph نداشت.

جست‌وجوی package concrete `gog.my_project.data_base.models.eloquent` در `src/main/kotlin` ماژول Builder referenceای نیافت. AST و Renderer نیز Model-aware نیستند.
