# Model-backed Query DSL v1.4: Traceability Report

## Status

**Implementation Ready** — readiness قرارداد برای مرحله implementation است؛ در اجرای این گزارش هیچ کد، build یا test تغییر/اجرا نشده است. تصمیم‌های اصلی بر اساس source موجود بسته شدند.

## Objective

ردیابی هویت جدول و ستون در SELECT، JOIN، WHERE، UPDATE، INSERT و DELETE و تفکیک آن از alias، پارامتر runtime، CTE و expression؛ بدون تغییر source، test، Gradle، documentation یا baseline v1.3.

## Repository Evidence

Sourceهای بررسی‌شده: metadata و IModelBase در data_base/core؛ APIها و Builderهای query در data_base/query/{api,builder}؛ AST در data_base/query/ast؛ rendererها در query renderer؛ مدل‌ها و نمونه‌های v2 در data_base/query/example/src/main/kotlin/v2/queries؛ Gradle ماژول‌های query builder، query API، core، models:eloquent و example؛ تست TypedModelReferenceTest و گزارش v1.3.

Active code شامل typed table/select، String tableColumn/tableAttribute/cteColumn، condition selector/value، join، DML و rendererهاست. مدل‌های v2 شواهد use-site/example هستند. مسیرهای قدیمی reflection/CTE که comment یا غیرفعال‌اند، پشتیبانی جاری محسوب نشدند. یافته‌های v1.3 با source جاری دوباره بررسی شدند.

Dependency evidence: query builder در production به core، query AST و query API وابسته است و dependency concrete به models:eloquent ندارد؛ example آن را مصرف می‌کند. Graph/build task اجرا نشد.

## Model v1.3 Baseline

**Evidence:** IQueryTableApi متد typed table(KClass<T>, alias?) و IQueryColumnsApi متد typed column(KClass<T>, KProperty1<T,R>) دارد. QueryTableBuilder و QueryColumnsBuilder QBTable/QBColumn را resolve و به AST موجود می‌نویسند. ModelTableAliasContext بین typed root table و SELECT projection هماهنگی می‌دهد.

**Interpretation:** Root TABLE و SELECT baseline اثبات‌شده‌اند؛ context موجود JOIN/WHERE/DML child builderها را پوشش نمی‌دهد.

**Decision:** TABLE و root SELECT برابر Already Supported؛ سایر نقاط مستقل ارزیابی می‌شوند.

## Existing Model-backed APIs

| سطح | Evidence → Interpretation → Decision |
|---|---|
| Root TABLE | typed API → QueryTableBuilder → table AST → renderer فعال است؛ Already Supported و حفظ شود. |
| SELECT | typed API → QueryColumnsBuilder → column AST → renderer فعال است؛ QBColumn.name و default alias مصرف می‌شوند؛ root projection Already Supported. |

## Column Reference Traceability

**Evidence:** IQueryColumnsBaseApi و QueryColumnsBaseBuilder یک reference را به IQueryColumnsBaseAst می‌سازند. AST table/alias/column/CTE fields دارد و renderer آن را مصرف می‌کند. Renderer/Executor به Model metadata وابسته نیستند.

**Interpretation:** metadata lookup در Builder و lowering به AST موجود کفایت می‌کند؛ نیاز اصلی occurrence alias برای child queryهاست.

**Decision:** Model KClass/KProperty در Builder resolve شود؛ AST/renderer جدید ساخته نشود.

## SELECT Traceability

**Evidence:** typed SELECT جاری QBColumn.name و QBColumn.alias را resolve می‌کند. tableColumn(alias,name) نیز فعال است. tableAttribute(String) raw text را می‌پذیرد.

**Interpretation:** root projection پشتیبانی می‌شود؛ tableAttribute با شباهت ظاهری به نام ستون به schema reference تبدیل نمی‌شود.

**Decision:** Root SELECT Already Supported؛ برای joined occurrence alias صریح per reference Adopt؛ tableAttribute به صورت String باقی و expression typing Defer.

## JOIN Traceability

**Evidence:** QueryJoinsItemBuilder child table و condition را می‌سازد، اما ModelTableAliasContext ریشه را به آن‌ها منتقل نمی‌کند. condition AST دو operand را نگه می‌دارد و renderer هر دو را render می‌کند. نمونه v2 از دو tableColumn(alias,name) استفاده می‌کند.

**Interpretation:** alias propagation خودکار اثبات نشده و KClass→alias برای self-join مبهم است.

**Decision:** هر دو سمت ON با typed column operand و tableAlias صریح occurrence ساخته شوند. هر سمت مستقل است؛ self-join با دو alias صریح حل می‌شود.

## WHERE Traceability

**Evidence:** sideSelector block از IQueryColumnsBaseApi را به column AST تبدیل می‌کند. sideValue(block) column operand است، درحالی‌که sideValue(name,value) و collection پارامتر runtime می‌سازند. مثال invalid IS 1 موجود است.

**Interpretation:** selector/column operand قابل Model-backed شدن‌اند؛ value و collection هویت دیگری دارند. Kotlin type هیچ SQL operator validation را ثابت نمی‌کند.

**Decision:** typed WHERE selector و column operand Adopt؛ value/collection API حفظ شود؛ مثال IS 1 دست‌نخورده بماند و validation تازه ادعا نشود.

## UPDATE Traceability

**Evidence:** update AST فیلدهای columnName، columnAlias و columnTag دارد. Renderer target را با qualifier alias می‌سازد و مقدار را از parameter tag می‌گیرد. WHERE مسیر conditions جدا دارد.

**Interpretation:** metadata ستون و tag/value جاری قابل حفظ‌اند، اما renderer برای target qualifier می‌خواهد.

**Decision:** typed SET target Adopt؛ QBColumn.name ستون، value runtime parameter، tag مطابق قرارداد جاری. Default QBTable.alias یا alias صریح باید پس از resolution غیرخالی باشد؛ در غیر این صورت Builder IllegalArgumentException بدهد. WHERE با typed operand و alias occurrence صریح.

## INSERT Traceability

**Evidence:** insert AST نام target و parameter tag را جدا دارد؛ renderer target و bind value را جدا مصرف می‌کند.

**Interpretation:** QBColumn.name target را مشخص می‌کند و value همچنان runtime است؛ qualifier لازم نیست.

**Decision:** typed INSERT target Adopt؛ String API جاری حفظ شود.

## DELETE Traceability

**Evidence:** typed table از v1.3 موجود است؛ WHERE از condition AST استفاده می‌کند؛ addTarget(String) به AST رشته target/alias می‌دهد.

**Interpretation:** addTarget معنای Model column identity ندارد.

**Decision:** typed WHERE Adopt؛ addTarget String باقی بماند.

## CTE Traceability

**Evidence:** مسیر active cte/with/cteColumn دارد؛ lookupهای قدیمی reflection در comment/غیرفعال‌اند. CTE output از query select/alias ناشی می‌شود.

**Interpretation:** CTE output identity از physical model column مستقل است.

**Decision:** Model-backed CTE column Defer تا وقتی CTE schema contract مستقل و قابل اتکا موجود باشد.

## Expression / Table Attribute Traceability

**Evidence:** tableAttribute(String) فعال است و raw attribute را به AST/renderer می‌دهد؛ Expression AST مستقل مشاهده نشد.

**Interpretation:** رشته ممکن است expression باشد و Model property بودنش ثابت نیست.

**Decision:** typed expression/tableAttribute Defer؛ abstraction جدید رد شود.

## Alias Analysis

**Owner-provided contract clarification:** QBTable.name نام جدول؛ QBTable.alias default SQL table alias؛ QBColumn.name نام database column؛ QBColumn.alias default SELECT alias؛ explicit SELECT alias بر default مقدم است.

**Repository Evidence:** v1.3 alias context فقط root SELECT/table را هماهنگ می‌کند؛ join/where child context جداست. UPDATE renderer به qualifier نیاز دارد. CTE alias جداگانه در AST نگهداری می‌شود.

**Interpretation:** alias مربوط به query occurrence است، نه Model identity؛ یک KClass می‌تواند چند occurrence داشته باشد.

**Decision:** alias هر column operand در JOIN/WHERE/DML صریح و occurrence-specific باشد و بر default table alias مقدم شود. خالی بودن operand alias یعنی بدون qualifier؛ اما UPDATE effective alias خالی ممنوع است. QBColumn.alias فقط default SELECT output alias است و explicit projection alias بر آن غالب است. CTE alias مستقل می‌ماند.

## Type Safety Analysis

**Evidence:** KClass/KProperty generic type و Kotlin property metadata در API قابل مشاهده است.

**Interpretation:** این type صرفاً Kotlin-side reference/value compatibility است.

**Decision:** SQL type، SQL nullability، operator compatibility، coercion و ResultSet mapping استنتاج نشود.

## Model vs Query Parameter Boundary

**Evidence:** column operand و sideValue(name,value)/collection در Builder و AST branchهای جدا دارند؛ DML target و value نیز جدا هستند.

**Interpretation:** schema identity و runtime parameter یک مفهوم نیستند.

**Decision:** Model property → schema/column identity؛ sideValue، collection، addParam، INSERT/UPDATE value → runtime parameter/value. Model property هیچ‌گاه جای value را نمی‌گیرد.

## Candidate Feature Matrix

| Location | Decision | Evidence → Interpretation → Reason |

| Root SELECT | Already Supported | API→Builder→AST→Renderer جاری و typed است؛ baseline حفظ می‌شود. |
| TABLE | Already Supported | typed API و render path جاری است؛ String API نیز باقی می‌ماند. |
| SELECT joined occurrence | Adopt | root context به join نمی‌رسد؛ qualifier صریح لازم است. |

| UPDATE SET/WHERE | Adopt | target/tag و condition fields موجودند؛ UPDATE alias باید nonempty باشد. |
| INSERT target | Adopt | target name و parameter binding جدا هستند. |

## API Contract

قرارداد دقیق پیشنهادی؛ generic bound روی methodهای API:

~~~kotlin
// IQueryColumnsBaseApi
fun <T : IModelBase, R> tableColumn(table: KClass<T>, property: KProperty1<T, R>, tableAlias: String): IQueryColumnsBaseApi

// IQueryColumnsApi: overload برای explicit joined occurrence
fun <T : IModelBase, R> column(table: KClass<T>, property: KProperty1<T, R>, tableAlias: String): IQueryColumnsApi

// IQueryColumnUpdateApi
fun <T : IModelBase, R> column(table: KClass<T>, property: KProperty1<T, R>, value: R, tableAlias: String? = null): IQueryColumnUpdateApi

// IQueryColumnInsertApi
fun <T : IModelBase, R> column(table: KClass<T>, property: KProperty1<T, R>, value: R): IQueryColumnInsertApi
~~~

String overloadهای فعلی حفظ شوند. Base operand alias صریح و occurrence-specific است؛ alias خالی یعنی بدون qualifier. UPDATE null یعنی default QBTable.alias و empty effective alias خطا. INSERT qualifier نمی‌خواهد. نام DB فقط QBColumn.name است؛ fallback به Kotlin property name ممنوع. Metadata ناقص/خالی با IllegalArgumentException رد شود، مطابق v1.3.

## AST Contract

**Evidence:** base column/condition/join و DML AST فیلدهای column name، alias، tag/value موجود دارند.

**Interpretation:** موجودی AST برای physical columns کافی است.

**Decision:** QBColumn.name → existing column field؛ effective alias → existing alias field؛ runtime value → existing parameter/tag. Model-specific یا generic operand node اضافه نشود.

## Builder Contract

Lookup annotation فقط در Builderهای API-facing انجام شود. Base column builder برای هر operand مستقل metadata resolve و AST موجود تولید کند. JOIN هر دو طرف را مستقل بسازد. UPDATE default/explicit alias را resolve و خالی را رد کند؛ INSERT target و parameter tag را حفظ کند. KClass→alias global context لازم نیست، پس ترتیب ساخت و self-join مبهم نمی‌شود.

## Renderer Contract

Rendererهای column, condition, join, update, insert, delete از AST مصرف می‌کنند و Model reflection ندارند. AST lowering نیاز را پوشش می‌دهد؛ renderer/executor بدون تغییر می‌مانند. UPDATE empty alias با Builder guard مهار می‌شود.

## Backward Compatibility

تمام String/block APIهای tableColumn, table, column, cteColumn, tableAttribute, DML column و addTarget حفظ شوند. Typed overloadها افزایشی باشند. مدل‌ها، annotationها، v1.3 API و مثال‌های v1 تغییر نکنند. JVM/source/binary collisionها باید در implementation compile verification شوند؛ در این مرحله build انجام نشده است.

## Test / Example Impact

Test plan آینده: metadata و no property-name fallback؛ root/join/default/explicit alias و ترتیب declaration؛ self-join با دو alias؛ WHERE/JOIN column operands در برابر parameters/collections؛ LIKE/IS NULL و حفظ مثال invalid IS 1؛ UPDATE SET/WHERE و empty alias rejection؛ INSERT tags/value؛ DELETE target و WHERE؛ AST/SQL rendering؛ String API regression؛ dependency verification برای عدم نیاز Query Builder به concrete Model. تست/build اجرا نشد.

## Adopted Features

- Typed operand: AST موجود → Builderهای root/child فاقد metadata resolution → resolve و lower در Builder با alias صریح per occurrence.
- JOIN/WHERE cross-table: AST دو operand دارد → هر occurrence identity/alias خودش را دارد → typed operands Adopt.
- UPDATE: AST target/tag دارد و renderer qualifier می‌خواهد → typed target و nonempty alias guard Adopt.
- INSERT: target و parameter مستقل‌اند → typed target Adopt.
- DELETE: condition AST قابل reuse است و addTarget alias/string است → typed WHERE Adopt و target String حفظ شود.
- Root TABLE/SELECT: مسیر کامل جاری اثبات شد → Already Supported.

## Deferred Features

Model-backed CTE output، tableAttribute/expression، Kotlin-to-SQL type mapping، SQL nullability/operator checking، ResultSet mapping، ORM/CRUD و Model-specific AST.

## Rejected Features

نگاشت global KClass→alias (به‌خاطر self-join)، Model property به‌عنوان parameter، generic expression/operand AST بدون کمبود اثبات‌شده، renderer/executor reflection، و تبدیل addTarget به Model column رد می‌شوند.

## Unresolved Decisions

تصمیم معماری اصلی unresolved نیست. Compile-time/JVM signature collision و source/binary compatibility verification، اجرای تست‌های تعریف‌شده و verify نهایی SQL نمونه‌ها متعلق به مرحله implementation هستند و مانع بسته‌شدن قرارداد traceability نیستند.

## Final Plan 1.4 Contract

~~~text
Already supported: typed root TABLE و SELECT v1.3.
Adopt for implementation: typed joined SELECT qualifier؛ typed physical column operands در JOIN/WHERE؛ typed UPDATE و INSERT targets؛ typed DELETE WHERE.
Keep String/value based: String APIهای فعلی، runtime values/collections و DELETE addTarget.
Defer: Model-backed CTE، tableAttribute/expression و type/nullability inference.
Reject: global KClass-to-alias map، Model-as-parameter، Model-specific AST و renderer reflection.
Unresolved: هیچ تصمیم معماری اصلی؛ compile/JVM compatibility verification در implementation.
API owners/signatures: IQueryColumnsBaseApi.tableColumn(KClass,KProperty1,String); IQueryColumnsApi.column(KClass,KProperty1,String); IQueryColumnUpdateApi.column(KClass,KProperty1,R,String?); IQueryColumnInsertApi.column(KClass,KProperty1,R).
Alias and identity rules: QBTable.name physical table؛ QBColumn.name physical column؛ QBTable.alias default table alias؛ QBColumn.alias default SELECT alias؛ column operand alias explicit per occurrence؛ UPDATE effective alias nonempty.
AST lowering: existing name/alias/tag/value fields؛ node جدید ندارد.
Builder resolution point: API-facing base column, UPDATE و INSERT builders؛ JOIN/WHERE operands independent.
Renderer/Executor impact: بدون تغییر و Model-unaware.
Dependency direction: Query Builder وابسته به core/AST/API؛ concrete Model module dependency اجباری نیست.
Backward compatibility: تمام String APIs و v1.3 semantics حفظ شوند؛ typed overloadها additive.
~~~
