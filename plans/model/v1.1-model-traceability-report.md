# Model v1.1: Traceability و تثبیت قرارداد فعلی Table Model

## Status

`Traceability complete; implementation readiness: Ready for Traceability`

## Objective

این گزارش semantics قابل اثبات infrastructure فعلی Model را از source repository ثبت می‌کند. شواهد فقط قراردادهای موجود را توصیف می‌کنند؛ metadata annotationها به‌تنهایی اثبات نمی‌کنند که runtime یا subsystem فعال آن‌ها را مصرف می‌کند.

## Existing Model Architecture

```text
IModelBase (core, empty interface)
    ↑
IModel (models:eloquent, empty interface)
    ↑
BaseModel (abstract, empty class)
    ↑
Users / UserPhones

QBTable / QBColumn (runtime-retained annotations in core)
```

دو Model موجود annotationها را نگه می‌دارند، اما هیچ مسیر فعال در repository برای خواندن آن‌ها پیدا نشد.

## IModelBase Analysis

- تعریف، marker interface خالی است و behavior یا dependency دیگری ندارد.
- `IModel` تنها implementer مستقیم پیدا شده است.
- Query API و builder نام `IModelBase` را در امضاها و importهای comment‌شده دارند؛ هیچ API فعال مبتنی بر آن پیدا نشد.
- در نتیجه، نقش قراردادی فعلی آن محدود به marker در زنجیرهٔ inheritance است؛ دلیل تاریخی ایجاد آن از source قابل تعیین نیست.

## IModel Analysis

- قرارداد خالی است و فقط `IModelBase` را گسترش می‌دهد.
- consumer مستقیمی جز `BaseModel` پیدا نشد.
- جداسازی معنایی ممکن است هدف طراحی بوده باشد، اما repository آن را توضیح نمی‌دهد؛ این هدف قطعی نیست.
- امکان حذف معماری از روی مصرف فعلی قابل ارزیابی است، ولی این traceability مجوز حذف یا refactor نیست.

## BaseModel Analysis

- کلاس abstract هیچ property یا method ندارد.
- `Users` و `UserPhones` هر دو از آن ارث می‌برند.
- abstract بودن در source توضیح داده نشده و reflection یا construction framework وابسته‌ای پیدا نشد.
- مشاهدهٔ فعلی: کلاس پایهٔ خالی برای inheritance است؛ اینکه صرفاً convenience بوده، از evidence قطعی نیست.

## QBTable Analysis

تعریف دارای `@Target(CLASS)` و `@Retention(RUNTIME)` با دو مقدار `String` پیش‌فرض `""` است.

### `name`

- مدل‌ها مقادیری مانند `user_users` و `user_phones` ثبت می‌کنند؛ این الگو با نام جدول سازگار است، اما annotation به‌تنهایی معنای رسمی یا الزام به database table را تضمین نمی‌کند.
- مقدار در کد Query فعال خوانده یا به SQL داده نمی‌شود.
- validation برای blank، schema qualification یا حروف بزرگ/کوچک پیدا نشد.
- quoting مربوط به این annotation قابل اثبات نیست؛ renderer مسیر مدل‌محور فعال ندارد.

### `alias`

- مدل‌ها aliasهایی مانند `uu` و `up` دارند.
- در block غیرفعال builder، مقدار قرار بود به `ast.tableAlias` منتقل شود. API فعال table همچنان رشتهٔ table و alias را جداگانه می‌پذیرد.
- این شواهد با alias جدول سازگار است، اما SQL نمونهٔ حاصل از annotation مدل تولید نمی‌شود؛ معنای دقیق runtime تثبیت نشده است.

### Runtime

`Runtime consumer: None found` برای consumer فعال. `findAnnotation<QBTable>()` فقط در بدنهٔ comment‌شده دیده شد.

## QBColumn Analysis

تعریف دارای `@Target(PROPERTY)` و `@Retention(RUNTIME)` است؛ مقادیر `name` و `alias` رشته‌ای و `primaryKey` بولی هستند.

### `name`

- propertyهای مدل‌ها مقادیر `id`, `name`, `family`, `age`, `phone`, `user_id` دارند؛ الگو با نام ستون سازگار است.
- usage فعال در query rendering یا metadata processing پیدا نشد.
- validation، quoting، schema/namespace و case behavior قابل اثبات نیست.

### `alias`

- مدل‌ها aliasهایی مانند `u_user_id` و `up_phone` ثبت می‌کنند.
- کد comment‌شدهٔ builder آن را به `ast.columnAlias` انتقال می‌داد، در کنار مقدار `name` برای ستون.
- چون مسیر غیرفعال است، `SELECT ... AS ...` یا کاربرد runtime دیگری را نمی‌توان قرارداد فعال دانست.

### `primaryKey`

- روی یک property در هر یک از `Users` و `UserPhones` مقدار true است.
- هیچ مصرف‌کنندهٔ فعال در query, migration, mapping یا runtime مدل پیدا نشد؛ فعلاً annotation metadata صرف است.
- هر annotation فقط یک مقدار بولی روی یک property نگه می‌دارد؛ نمونه‌های فعلی با single-column علامت‌گذاری سازگارند. پشتیبانی قراردادی از کلید مرکب وجود ندارد.

`Runtime consumer: None found` برای consumer فعال `QBColumn`; دسترسی reflection فقط در block comment‌شده است.

## Model → Query Builder Traceability

`Query Builder dependency: None found` در مسیر اجرایی فعال. APIهای مدل‌محور و پیاده‌سازی reflection comment شده‌اند؛ APIهای فعال مقادیر رشته‌ای دستی می‌گیرند. بنابراین طرح قبلی metadata access فقط قصد/کد غیرفعال را نشان می‌دهد.

## Model → ResultSet Traceability

`ResultSet → Model mapping: Not implemented` بر اساس جست‌وجوی source. وجود `ResultSet` در اجرای query یا Migration برای خواندن نتیجه/حالت‌های Migration است و به‌تنهایی mapping به Model نیست. Mapper، constructor mapping، property assignment یا factory مدل پیدا نشد.

## Model → Migration Traceability

`Migration → Model metadata dependency: None found`. Migrationها schema را از API/ASTهای خود تعریف می‌کنند. وجود عملیات primary key یا نام‌های مشابه در Migration مستقل از annotationهای Model است؛ اتصال خودکار به Model evidence ندارد.

## Kotlin Type Semantics

نوع‌های property در دو Model به SQL type، validation، query generation یا mapping متصل نیستند. بنابراین نگاشت `Int`, `String?` به نوع DB یا nullability ستون از روی این repository قابل استنتاج نیست. Nullability فعلی صرفاً nullability نوع Kotlin است.

## Constructor Semantics

- هر دو Model موجود constructor بدون آرگومان و propertyهای دارای default دارند.
- propertyها immutable (`val`) هستند.
- reflection instantiation یا mapping مصرف‌کننده‌ای برای آن‌ها پیدا نشد.
- در نتیجه نه no-arg بودن به‌عنوان نیاز عمومی ثابت است، نه پشتیبانی از immutable Model توسط mapper؛ mapper فعلی وجود ندارد.

## Reflection Contract

- annotationها runtime-retained هستند.
- محل کشف فعال annotation یا خواندن metadata وجود ندارد.
- نمونه‌های `findAnnotation` داخل بدنه‌های comment‌شدهٔ Query Builder قرار دارند.
- caching و performance concern پیاده‌سازی‌شده‌ای پیدا نشد؛ با نبود مصرف فعال، نگرانی performance در قرارداد فعلی مطرح نشده است.

## Minimal Current Contract

```text
IModelBase: empty marker interface
IModel: empty subtype of IModelBase
BaseModel: empty abstract implementation path through IModel
QBTable: runtime-retained class annotation with string name/alias defaults
QBColumn: runtime-retained property annotation with string name/alias and Boolean primaryKey defaults
Users and UserPhones: examples carrying this metadata
Active metadata consumer: none found
```

metadataها در source وجود دارند؛ معنای table/column/alias فراتر از شکل و مقادیر نمونه‌ها هنوز به‌عنوان رفتار فعال repository تثبیت نشده است.

## Candidate Decision Matrix

| Capability | Decision | Rationale |
|---|---|---|
| Model marker | Adopt | زنجیرهٔ marker خالی واقعاً در source و inheritance مدل‌ها حاضر است. |
| Table name | Unresolved | مقدار نمونه با نام جدول سازگار است؛ مصرف فعال/تعریف اجرایی ندارد. |
| Table alias | Unresolved | مقدار و AST مقصد در کد comment‌شده دیده می‌شود؛ runtime فعال نیست. |
| Column name | Unresolved | مقدار نمونه با نام ستون سازگار است؛ مصرف فعال/تعریف اجرایی ندارد. |
| Column alias | Unresolved | AST مقصد در کد comment‌شده هست؛ semantics SQL فعال اثبات نشده. |
| Single Primary Key metadata | Adopt | property annotation مقدار بولی دارد و روی یک property در هر Model فعلی true است؛ مصرف رفتاری ندارد. |
| Composite Primary Key | Defer | annotation فعلی روی property است و metadata مدل مجموعه‌ای/مصرف مرکب ندارد. |
| Nullable metadata | Defer | nullability تنها در نوع Kotlin نمونه‌هاست؛ metadata یا mapping وجود ندارد. |
| Kotlin → DB type mapping | Defer | هیچ نگاشت مصرف‌شده‌ای پیدا نشد. |
| ResultSet → Model mapping | Defer | پیاده‌سازی پیدا نشد. |
| Model → Migration | Defer | اتصال خودکار پیدا نشد. |
| Relations | Defer | رابطهٔ مدل در این infrastructure پیدا نشد. |
| Repository / CRUD | Defer | abstraction یا رفتار CRUD در مسیر Model پیدا نشد. |

## Backward Compatibility

این traceability هیچ API یا source codeای را تغییر نداده است. تعهد source compatibility در این گزارش الزام اجرای آینده است، نه ادعای تغییر یا اثبات binary compatibility. نام‌های `IModelBase`, `IModel`, `BaseModel`, `QBTable`, `QBColumn`, `Users`, و `UserPhones` در source فعلی حاضرند.

## Architecture Boundary

تعریف marker و annotation در `data_base:core` است؛ دو نمونه در `data_base:models:eloquent` قرار دارند. Query API سابقاً مسیر مدل‌محور را نشان می‌دهد اما فعلاً comment شده و Query Builder فعال ورودی رشته‌ای دارد. بنابراین ارتباط تاریخی/مقصود احتمالی با Query Builder را می‌توان دید، اما subsystem فعال مالک metadata در runtime از evidence فعلی تعیین نمی‌شود. اتصال به Migration، Result Mapping یا ORM نیز ثابت نشده؛ صرف نام `eloquent` برای طبقه‌بندی به‌عنوان ORM کافی نیست.

## Deferred / Out of Scope

Composite key، nullable metadata، type mapping، ResultSet mapping، Migration generation از Model، relations، repository/CRUD و ORM behavior پیاده نشده و در traceability حاضر به قرارداد اضافه نمی‌شوند.

## Unresolved Decisions

- آیا `QBTable.name` و `QBColumn.name` رسماً identifier جدول/ستون هستند یا فقط مقدارهای مورد انتظار مصرف‌کنندهٔ آینده؟
- آیا aliasها قرارداد SQL `AS` دارند، و چه قواعد quoting/validation/case/schema بر آن‌ها اعمال می‌شود؟
- آیا `primaryKey` قرار بوده مصرف runtime داشته باشد یا صرفاً metadata است؟
- آیا مسیر مدل‌محور Query Builder باید در نسخهٔ بعد فعال شود؟
- نقش و ضرورت مستقل `IModel` در کنار `IModelBase` چیست؟
- آیا no-arg constructor و immutable properties محدودیت قراردادی‌اند یا فقط شکل مثال‌ها؟

## Final Contract

قرارداد قطعی فعلی محدود است به دو interface خالی در زنجیرهٔ marker، یک abstract base class خالی، دو annotation runtime-retained با فیلدهای مشخص‌شده، و دو نمونهٔ Model که آن metadata را حمل می‌کنند. مصرف فعال metadata، SQL behavior، mapping و اتصال به Migration اثبات نشده‌اند؛ در نتیجه semantic اجرایی table/column/alias و رفتار `primaryKey` unresolved باقی می‌ماند.

## Implementation Readiness

`Status: Ready for Traceability`

پیاده‌سازی feature از این گزارش آمادهٔ تصمیم‌گیری نیست، چون semantics نام‌ها و aliasها، نقش عملی `primaryKey` و مرز مصرف‌کنندهٔ metadata هنوز unresolved هستند. این نتیجه صرفاً وضعیت داده‌های فعلی repository را گزارش می‌کند؛ هیچ implementation انجام نشده است.
