# Plan 10.0 — Rename QueryRelationDeclaration to QueryDeclaration

## Status

**Implemented and Verified**

این گام، اولین تغییر کوچک و مستقل از مجموعهٔ Plan 10 است. قرارداد این گام فقط تغییر نام base class موجود است.

## Objective

نام base class فعلی QueryRelationDeclaration را به QueryDeclaration تغییر بده تا نقش آن به‌عنوان base class اختیاری برای تعریف Query روشن‌تر باشد.

این rename به‌تنهایی نباید معنای Relation، Query runtime یا اجرای Query را تغییر دهد.

## Current Contract to Preserve

کلاس مقصد باید همان generic parameter و inheritance فعلی را حفظ کند:

~~~kotlin
abstract class QueryDeclaration<P> : IQueryRelation<P>
~~~

همچنین موارد زیر بدون تغییر باقی می‌مانند:

* abstract property با نام relationName
* override مربوط به queryRelation(params: P)
* helper protected و final به نام buildQueryRelation(block)
* ساخت QueryRelation با relationName و this::class به‌عنوان declaration owner
* constructor و visibility فعلی
* رفتار فعلی و delegation به primitive موجود ساخت QueryRelation

امضای helper فعلی:

~~~kotlin
protected final fun buildQueryRelation(
    block: IQueryRenderSelectApi.() -> Unit,
): QueryRelation
~~~

## Scope

* نام کلاس QueryRelationDeclaration به QueryDeclaration تغییر کند.
* تمام referenceهایی که مستقیماً به این base class اشاره می‌کنند، در production، example، test، Help metadata و مستندات مرتبط به نام جدید منتقل شوند.
* test یا fixtureای که مشخصاً نام همین base class را دارد، در صورت نیاز برای حذف reference قدیمی rename شود.
* generic parameter، inheritance، constructor، اعضا و رفتار کلاس حفظ شوند.
* IQueryRelation و QueryRelation runtime type بدون تغییر باقی بمانند.
* SQL rendering، parameter handling، Relation composition، typed-output resolution و execution behavior بدون تغییر بمانند.

## Explicitly Out of Scope

این گام نباید موارد زیر را rename یا redesign کند:

* IQueryRelation
* QueryRelation
* relationName
* queryRelation(...)
* factoryها یا APIهای composition مربوط به Relation
* CTE APIها یا annotationها
* Query rendering، AST، execution یا result contract

این تصمیم‌ها به گام‌های بعدی Plan 10.x موکول هستند. نام‌های بالا در این گام حفظ می‌شوند، حتی اگر بعداً در Plan 10.x جداگانه بررسی شوند.

## Acceptance Criteria

1. base class با نام QueryDeclaration در package فعلی ارائه شود.
2. تمام referenceهای اجرایی و مستقیم به QueryRelationDeclaration به QueryDeclaration منتقل شده باشند.
3. IQueryRelation implementationهای مستقیم همچنان بدون تغییر معتبر باشند.
4. inheritance از QueryDeclaration همان metadata و رفتار قبلی را تولید کند.
5. هیچ تغییر نام یا تغییر رفتاری نامرتبطی وارد نشود.
6. تست‌های مرتبط موجود موفق باشند.
7. جست‌وجوی repository در source، example، test و Help تأیید کند که reference ناخواسته‌ای به نام قدیمی باقی نمانده است. ذکر نام قدیمی در همین سند به‌عنوان نام مبدأ rename مجاز است.
