# قرارداد و ساختار Collection

کد عمومی ماژول در package `gog.my_project.collection` قرار دارد. قرارداد در `ICollection.kt` تعریف شده و پیاده‌سازی فعلی آن در `Collection.kt` است.

## دو نوع اصلی

- `ICollection<T>` رابطی است که عملیات پشتیبانی‌شده را اعلام می‌کند.
- `Collection<T>` پیاده‌سازی فعلی رابط است و عناصر را در یک `MutableList<T>` داخلی نگه می‌دارد.

```kotlin
val values: ICollection<String> = Collection()
```

استفاده از interface در نوع متغیر، وابستگی کد مصرف‌کننده را به قرارداد محدود می‌کند؛ برای ساختن نمونه در حال حاضر از `Collection<T>()` استفاده می‌شود.

## عملیات موجود

`ICollection<T>` این اعضا را دارد: `add`, `forEach`, `filter`, `map`, `firstOrNull`, `toList`, `get(index)` و `size`. این API، iterator یا عملیات حذف و مرتب‌سازی تعریف نمی‌کند؛ برای آن‌ها باید از ساختار مناسب دیگری استفاده کنید.

## رفتار ذخیره‌سازی

پیاده‌سازی عناصر را به انتهای فهرست داخلی اضافه می‌کند؛ بنابراین ترتیب ورود حفظ می‌شود و مقادیر تکراری هم نگه داشته می‌شوند. عناصر به‌صورت reference ذخیره می‌شوند: Collection از objectهای mutable کپی عمیق نمی‌سازد. پس تغییر یک شیء mutable از طریق reference دیگر، هنگام خواندن همان عنصر از Collection نیز قابل مشاهده است.

`filter()` و `map()` یک Collection تازه می‌سازند؛ تغییر ساختار Collection خروجی، ساختار منبع را تغییر نمی‌دهد. با این حال، اگر عناصر خروجی همان objectهای mutable منبع باشند، آن objectها کپی نشده‌اند. `toList()` نیز کپی سطحی از ساختار فهرست می‌دهد، نه کپی عمیق عناصر.

## هم‌زمانی و نوع استاندارد Kotlin

پیاده‌سازی فعلی از `MutableList` بدون synchronization استفاده می‌کند. ایمنی دسترسی یا تغییر هم‌زمان تضمین نشده است؛ دسترسی چندریسمانی را با هماهنگی بیرونی انجام دهید.

`ICollection<T>` یک API اختصاصی است و خودبه‌خود `Iterable<T>` یا `kotlin.collections.Collection<T>` نیست. برای APIهایی که `List<T>` می‌خواهند، از [تبدیل به List](to-list.md) استفاده کنید.
